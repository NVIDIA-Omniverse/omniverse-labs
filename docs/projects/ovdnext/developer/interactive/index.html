RECORD ONCE. INSPECT THE RECORDED STATE.

What is an OVD file?

PhysX generates .ovd binary recordings using the OmniPVD writer classes in the PhysX SDK. OVD Viewer is a viewer/inspector application that uses the SDK's OmniPVD reader classes to read those recordings and live streams. The recorded data describes object and attribute definitions, object lifetimes, property updates and frame markers, which OVD Viewer uses to visualize the state at a selected frame.

Your task: a teammate asks what mass and collision margin their simulated body had. Open the same capture they recorded, select its frame and read the body's mass and its shape's contact offset. Keep the capture identity with the result so they can reproduce it.

These values come from the worked capture used below. Object IDs are local to this capture/load. The available data depends on the producer's SDK, recording selection and supported writes. Playback inspects recorded state without re-running the simulation.

Frames are recording markers, not universal application-step numbers. Verify the producer's pre/post mapping. Unsupported or unwritten data stays unavailable; recording cannot recover attributes the producer never emitted.

Contact manifold

PointActor pairPosition · world XYZNormal · world XYZSeparationNormal impulse

Points, normals, separations and impulses come from the selected frame’s PxScene.pairsContact* arrays. Pair order comes from pairsContactCounts and ordered producer handles, resolved to recorded object IDs. Positive separation can coexist with a contact; the contact distance is not a penetration depth. The native viewer draws contacts only with the matching Pre-sim frame selected or in focus, using the following Post-sim report. A BODY → ITS SHAPE → TWO RECORDED VALUES

Read mass and contact offset.

Use multi_geom.ovd, scene 3, zero-based frame 2. Start with PxRigidDynamic #11 in the rigid-body lab above.

  1. 1
    Select the body. Read mass = 10.

    Click body #11 in the geometry or object buttons. Its inspector shows mass, pose and velocity. This is a recorded PxF32 value, not a mass inferred from the drawn size.

  2. 2
    Follow shapes → #10.

    The body's shapes reference leads to PxShape #10. Read contactOffset ≈ 0.02 and restOffset = 0 there. Contact offset belongs to the shape; mass belongs to the body.

  3. 3
    Keep the frame and availability with the answer.

    Both values are present at frame 2. Contact offset is a physical distance used to start contact generation. Compare it with the other shape’s contact offset; the pair’s margins add together. Scrub the lab to compare another frame. Use the producer's unit convention rather than assuming metres or kilograms.

Read the same two values in Python

import struct

# After load_capture, with these IDs discovered in multi_geom.ovd:
view = opened.session.presentation(3, 2, inspect_ids=[11, 10])
assert view.ready and view.request_applied
assert (view.scene_id, view.frame) == (3, 2)
objects = {obj.id: obj for obj in view.instances(0, 100)}
for object_id, name in [(11, "mass"), (10, "contactOffset")]:
    prop = next(p for p in view.properties(objects[object_id].class_id)
                if p.name == name)
    assert view.property_availability(object_id, prop.id) == "present"
    assert prop.native_type == "PxF32" and not prop.array
    value, = struct.unpack("<f", view.read(object_id, prop.id, 0, 4))
    print(object_id, name, value)
# 11 mass 10.0
# 10 contactOffset 0.019999999552965164

This excerpt runs inside the complete package-loading example, before closing opened. These IDs and the first 100 objects are specific to this small fixture; discover and page objects for another capture. The buttons above navigate this guide's recorded data, without opening a TCP connection.

  1. 1
    Connect the producer.

    Open Live, set the port and choose Listen. The viewer is the TCP listener; configure your PhysX producer to connect to it. With the connection active, open Live → Recording selection….

  2. 2
    Select the body in the recording catalog.

    Use Name prefix → Find or the parent rows to locate it, and check its row under Selected. A whole articulation includes its links and joints. Choose Primary or + Secondary: these are producer policies, not individual attribute switches. All permitted explicitly requests the full permitted scope; an empty Selected list does not.

  3. 3
    Apply, read the acknowledgement, then wait for a frame.

    Press Apply and check the producer's response and Actual policy. The producer may narrow or deny your request. Applied means recording restarted; the new segment appears in follow-latest only after a complete frame arrives.

VIEWPORT PICK ≠ RECORDER SELECTIONPicking a body to read its mass only changes inspection. It never changes the producer's scope. The recording-selection panel still targets the live producer when you display an older file.

ONE CONNECTION, ONE RECORDINGApply keeps the segments in the same retained recording. When a new segment is adopted, object selection resets; camera and render settings remain. Save as on the displayed live capture freezes it.

Selection and catalog discovery require separate advertised producer capabilities. Telemetry-only streaming still works without them. OVD CAPTURE + SEPARATE JSON FINDINGS

Side-load evidence beside the capture.

A CPU control run reports an energy increase around a body's tilt change. You want to inspect the seven measured frames behind that warning. Side-load its JSON and select the finding without modifying the OVD.

  1. 1
    Open the OVD, then import the JSON.

    Choose Import evidence JSON in the application menu or Evidence window. The viewer accepts SDK physx.ovd.inspection-evidence v1/v2 and the ovdnext.timeline-evidence v1 envelope. For a live capture, save it and open the saved file first to enable verified binding.

  2. 2
    Pick a finding and its capture role.

    The Evidence window lists imported sets and findings. Choose Left or Right explicitly if both roles match. Read the measured value, units, tolerance, source and assumptions. A bare SDK record can remain readable even without a hash that binds it to the open capture.

  3. 3
    Select a point, then use Go to.

    A timeline marker selects finding details without moving the playhead. Select the indicated scene and a clip covering its exact frame; Go to then pauses there and selects the verified object. If it is disabled, read the missing prerequisite instead of navigating to an approximate frame.

References have their own representation, too. The fixture's shapes property has zero raw bytes but a nonempty reference list. Use view.references(instance_id, property_id); a byte preview alone is not the full typed value.

Why reads are bounded

A presentation copies a bounded projection of the captured state. Default byte reads are at most 64 KiB; the reference explains explicit windows, record requests and the 128 MiB copy budget. Keep availability, liveness and truncation in results. Do not fill gaps by mixing data from different frames.

WHY ARE THERE CONTACTS BEFORE THE SURFACES TOUCH?

Contact offset is a physical margin.

A box approaches the ground. Inspect PxShape #10 on body #11 and ground PxShape #7 on body #8 in multi_geom.ovd, scene 3, frame 2. Each records contactOffset ≈ 0.02 and restOffset = 0. PhysX starts generating contacts when their surface separation falls below the sum of their contact offsets—about 0.04 scene units.

RECORDED OFFSETS · ADJUSTABLE ILLUSTRATED GAP

Box → ground

Schematic using the captured offsets, not a simulation or a replay of the recorded trajectory. The gap is illustrative; dashed margins are not enlarged collision geometry. Assume collision is enabled for this pair.

  1. 1
    Add the contact offsets.

    0.02 + 0.02 ≈ 0.04. At a gap of 0.03, contacts can already be generated while the collision surfaces are still separated. At 0.06, they are outside this contact distance.

  2. 2
    Read rest offset separately.

    0 + 0 = 0. The pair’s target separation at rest is zero: the surfaces should settle touching. The contact-generation margin does not mean the box must stop 0.04 above the ground.

  3. 3
    Inspect the step’s contacts on Pre-sim.

    In OVD Viewer, enable Contacts and select or focus the matching Pre-sim frame. Compare the recorded contact separation and normal impulse in the contact example. Positive separation can have a contact; contact generation and resting separation are different quantities.
