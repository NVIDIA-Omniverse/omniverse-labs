Before you begin

This sample connects your current Blender scene to an external Omniverse runtime. Use your own scene, open a .blend file, or import USD using Blender’s normal workflow.

You needFor the 0.2 package
BlenderUse Blender 5.2.1 LTS. Install Blender separately.
PlatformWindows x64 or Linux x64. ARM and macOS are unsupported.
GraphicsA compatible NVIDIA RTX GPU and driver. Linux rendering needs a Vulkan-capable display session.
PackageThe complete matched platform ZIP. Keep its add-on, runtime, manifest and installer together.

See platforms and runtime versions for compatibility details. This is an experimental integration with a supported feature subset; output and behavior can differ from Cycles and EEVEE.

01 / INSTALL

Install or upgrade

  1. Download the complete Windows x64 or Linux x64 package from the Blender 0.2.0 release, then extract it. Run the installer from this extracted folder; do not select the outer ZIP in Blender’s Add-ons menu.
  2. Close Blender. Open a terminal in the extracted folder and run the command for your platform, replacing the example Blender path.

Windows

install.bat "C:\path\to\Blender\blender.exe"

Linux

sh install.sh "/path/to/blender"
  1. Wait for installation and renderer warm-up. Warm-up can take several minutes while shader caches are prepared; progress appears every 30 seconds.
  2. Start Blender normally. Confirm the ovrtx Blender Example add-on is enabled, then select ovrtx Example as the render engine.

The installer uses Blender’s bundled Python and the local package. Rendering and physics run outside Blender. To upgrade an existing 0.2 installation, close Blender and run the new package’s installer. For an earlier integration, we recommend using a separate Blender settings folder.

02 / RENDER

Render a scene

  1. Open a demo scene or create one with an object, a light and a camera. Blender’s default scene includes all three. Save a working copy.
  2. In Render Properties, select ovrtx Example. Switch the 3D Viewport to Rendered shading. The worker starts when rendering is requested.
  3. Wait for a textured image and check ovrtx Session in Render Properties. Orbit the view, move an object, and adjust a supported light or material value to see the changes.
  4. Choose the active scene camera and output resolution. Press F12 to render that camera.
  5. When rendering completes, use Image → Save As in Render Result to save the image.

Color and anti-aliasing. Scene-linear HDR uses Blender’s color-management transform; LDR arrives already display-encoded. Final supersampling defaults to 2×2, while viewport supersampling defaults to 1×. Higher supersampling improves edges and costs more time and memory.

Rendering guide → Samples, RTPT quality, color, EXR output and animation.

03 / PHYSICS

Set up a falling cube

Start with a simple cube and a floor. Use the add-on’s OV panels in the Properties editor. CPU physics is the default, separate from the GPU used for RTX rendering.

↓Dynamic propMass + collider
Static floorFixed collision surface
  1. Add a cube above a thin box floor. Apply each object’s scale with Ctrl+A → Scale for a straightforward first setup.
  2. Select the cube. Open Physics Properties → OV Physics Body / Bone and click Assign OV Body. Choose Dynamic, leave it enabled, and set its mass.
  3. Inspect OV Colliders. Assigning a mesh body creates a Convex Hull collider; do not add a duplicate accidentally. Use Change Collider Shape if you want a Box collider.
  4. Select the floor, assign an OV body, and choose Static. Inspect its collider too.
  5. In Scene Properties → OV Physics Scene, choose Apply Scene and review gravity. Turn on physics indicators and collider wires; keep Blender’s Show Overlays enabled.
  6. With ovrtx Example and Rendered shading active, return the Timeline to its start frame and press Play. The expected result is a cube falling onto the floor.
  7. Stop playback and return to the start to reset. After changing physics setup, restart the preview from the start so the solver uses the new settings.

To tune friction and bounce, create an OV Physics Material in Material Properties and assign it explicitly to the collider.

04 / BAKE

Bake and render the motion

  1. Open Scene Properties → ovphysx Animation Bake. Set Initial Conditions and the Bake Start / Bake End range. Start with Sample Interval 1.
  2. Resolve any pending joint anchors or animation conflicts, then click Bake ovphysx Animation and wait for completion.
  3. Choose Activate Baked Playback. Scrub the Timeline and inspect editable keys in the Action Editor or Graph Editor.
  4. Save the .blend file with the baked Actions active. Press F12 for a chosen frame, or set an output directory and use Blender’s Render Animation.

The saved bake can play in Blender without the simulation worker. Use Restore Previous Animation before returning to live physics. See the bake walkthrough for output scope, cancellation and restoration.

Troubleshooting

SymptomFirst check
Engine is missingUse the settings folder you installed into and confirm the paired extension is enabled.
Installer exits with code 3Installation succeeded, but warm-up failed. Read the printed warm-up and worker log paths.
Blank viewportCheck Rendered shading, geometry, lights and the ovrtx Session message before changing materials.
Physics does not moveCheck enabled Dynamic body, collider, gravity, start frame and the panel’s runtime diagnostic.
Lost worker connectionRead the first error, then use Reconnect ovrtx Session or Restart ovrtx Worker.

Some Blender shaders are unsupported, so materials may look different from Cycles or EEVEE. Extra render passes, transparent backgrounds, skinned deformation, cloth and fluids are unavailable. GPU physics has narrower joint support than CPU physics. Rendering limitations · Physics limitations

Build and modify the integration

Edit your scene in Blender. The external runtime uses ovstage for scene representation, ovrtx for rendering, ovstream for frame transport, and ovphysx for simulation.

The 0.2 package uses a locked set of SDKs in an external worker. See the developer guide to find the code, make changes and test them.
